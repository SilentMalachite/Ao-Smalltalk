# P10-03: フレーム連鎖、abort 時の捕捉、Object>>halt

- 親フェーズ: [P10](../phases/P10.md)

## 目的

abort の瞬間に、解釈フレームの C++ 側の状態（temps、進行中の送信）まで含めてスタックを写せるようにする。SPEC §3.13（捕捉の意味論）、§3.3（`halt` の行）、§3.6（`Object>>halt`）。

## 手順

この PR を実装するセッションは `graphify-out/GRAPH_REPORT.md` を読み、`graphify path Interpreter abortEvaluation` と `graphify explain CallContext` で経路を取り、Serena で `ao::Interpreter::run`、`performSend`、`applyMethod`、`abortEvaluation`（`find_referencing_symbols` で Scheduler を含む全 abort 箇所）、`runAside`、`Scheduler::switchTo`、`Scheduler::terminate`、`afterResume`、`abandonAll`、`ao_Object_doesNotUnderstand_`、`NativeMethod::invoke`（変えないことの確認）の定義と参照を取ってからテストを赤にする。`Frame` の移動は `replace_symbol_body` で行い、C++ を大きく動かしたら `restart_language_server`。新規ファイル作成後は overview を取る。

GC をまたぐ呼び出しのあとは `receiver` / `args` を読み直す。捕捉は Smalltalk ヒープを割り当てず、スロットを逆順に外す。`finishFiber` の中では何もルートしない。

P1 以降のコードをこの PR 文書の範囲外で書かない。Kernel を触る PR なので走査テストが緑であること。`Session` の配線は P10-04。
