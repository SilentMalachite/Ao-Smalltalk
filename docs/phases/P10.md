# P10 — 事後デバッガ

## 結論

失敗（abort）の瞬間のスタックを巻き戻す前に写し、Ao.app の Debugger 窓で「フレーム一覧 / 失敗した送信を選択したソース / receiver と temps の値」を見る。評価の意味論、`ao_eval` の返り値、`ao --test`、CLI、イメージ形式は変えない。Proceed / Step は P11。

## 前提

P9（v1、1.0.0）緑。SPEC §1.4 と §5.4 と CLAUDE.md の禁止リストがデバッガを範囲外にしているので、**P10-01 で SPEC と CLAUDE.md を先に直す。** 計画書は [`docs/superpowers/plans/2026-09-26-p10-debugger.md`](../superpowers/plans/2026-09-26-p10-debugger.md)。改訂後の正本は SPEC §3.13（デバッガ）、§3.8（pc→ソース表）、§3.9（Debugger 窓）、§3.10（`ao_debug_*`）。

## 範囲

**やる:** コンパイラの pc→ソース表と temp 名、解釈フレームの連鎖（`CallContext::topFrame`）、abort 時のスナップショット、`Object>>halt`、セッションのソース表の拡張（ブロック、デバッグ情報、doIt）、`ao_set_debug_capture` と `ao_debug_*` ABI、Debugger 窓、Workspace の Debug ボタンと `process failed:` 表示、CHANGELOG。

**やらない:** 評価の中断、Proceed / Abort / Step / Restart / Debug it、デバッガ内の編集と Accept、ネイティブ呼び出しの連結、セレクタだけの強調、オペランドスタックの値の捕捉、`ao --test` のスタック出力、file-in / vendor のソース記録、Browser 連携、イメージ形式の変更、CompiledMethod のスロット追加。

## 仕様

- 連鎖は解釈フレームだけ。ネイティブは捕捉時に最内の進行中の送信から合成する。`NativeMethod::invoke` と高速路は変えない（SPEC §1.3）。
- 捕捉は `abortEvaluation` が最初の理由を固定した直後に `CallContext::debug`（sink）で行う。`terminate` / abandon の巻き戻し、後始末の間の再 abort、デバッガ自身の printString は捕捉しない。1 セッション 1 枠、ベース優先、最内 256 フレーム + 総数。
- pc→ソース表と temp 名は `MethodImage` の出力で、ソース表（セッション）に置く。イメージに書かない。CompiledMethod は 6 スロットのまま。
- `Object>>halt` は理由 `halt` で abort（P11 で「止める」に変わる）。
- ABI の読みは busy でも呼べ、printString / inspect / clear は最外の入口で busy なら拒む。
- Debugger 窓は frames / source / variables の 3 段。フレーム選択で pc の送信を UTF-16 換算で選択する。variables の値は選択時に遅延で読む。ダブルクリックで Inspector。generation が変わったら print / inspect をしない。
- Workspace: 評価のあとスナップショットがあれば Debug ボタン。`AO_OK` でスナップショットがあれば `process failed: <理由>`。

## 制約

Kernel ホットパスにインタプリタも連結も介入させない（SPEC §1.3）。GC しうる呼び出しのあとは `receiver` / `args` を読み直す。スナップショットは Smalltalk ヒープを割り当てずに作り、逆順に外す。`docs/bench.md` の比が悪化しない。
