# P13 — 評価の中断

## 結論

Ao.app のライブ評価を ⌘. / Smalltalk → Interrupt で止め、理由 `interrupted` のライブ Debugger に渡す。停止の形は step / Debug it と同じ命令境界で、Proceed は止めた命令から続ける。正本は SPEC §3.9「評価の中断」、§3.10「評価の中断」、§3.13「止める」、§6「評価の中断」。設計の理由は [`superpowers/specs/2026-09-30-evaluation-interrupt-design.md`](../superpowers/specs/2026-09-30-evaluation-interrupt-design.md)、計画書は [`superpowers/plans/2026-09-30-evaluation-interrupt.md`](../superpowers/plans/2026-09-30-evaluation-interrupt.md)。SPEC §6 はすべて `[x]`（自動テストの結果）。次のマイナー版（例: 1.2.0）に含める（SPEC §2.4）。

## 前提

P12 緑（1.1.0 リリース済み）。SPEC の P13 追記は先行コミット。実装は `ao_request_interrupt`、`ao_set_runloop_pump_hook`、インタプリタ後方ジャンプでの pump / フラグ確認、Ao.app の Interrupt メニューと RunLoop pump。

SPEC §6 の P13 のチェックは、自動テスト（`debug_abi_test` の `LiveDebug` / `DebugAbi` と `DebuggerWindowTests` / `ToolWindowTests`）の結果で付けた。Ao.app を手で操作する確認はまだしていない。

## 範囲

**やる:** 中断要求フラグ、RunLoop pump フック、インタプリタ safepoint での停止（理由 `interrupted`）、⌘. / Interrupt、busy 中の要求、ライブ off では止めない、関連の GoogleTest / XCTest。

**やらない:** CLI の `SIGINT`、評価のワーカースレッド化、ネイティブ safepoint での中断、fork / drain だけのプロセスの強制停止、Escape キー。

## 設計判断

- ベースが待っている評価プロセスだけを止める（`Scheduler::canHalt`）。それ以外はフラグを消費しない（8 件上限だけは理由 `interrupted` で abort）。
- 停止は命令境界。`Object>>halt` の「送信の値 nil」経路に乗せない。
- pump 未登録でもフラグだけで止まれる（テスト経路）。Ao.app は起動時に pump を登録する。
- `ao_request_interrupt` / `ao_set_runloop_pump_hook` は AbiEntry を取らない（busy 中も可）。
