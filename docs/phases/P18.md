# P18 — メソッドソースの永続化

## 結論

Accept と File In… でソース表に入ったメソッドのソースを、`.aoimage`（版 4）のソース節に保存し、ロードでソース表に戻す。ソースは Smalltalk のヒープに入れず、CompiledMethod の形もコンパイラも変えない。版 3 のイメージはソース無しで読む。正本は SPEC §3.9「Change Sorter（P16）」、§3.10「ソースはイメージのソース節に書く」、§3.11、§6「メソッドソースの永続化（P18）」。実装計画は [`superpowers/plans/2026-10-12-p18-method-source-persistence.md`](../superpowers/plans/2026-10-12-p18-method-source-persistence.md)、設計は [`superpowers/specs/2026-10-12-p18-method-source-persistence-design.md`](../superpowers/specs/2026-10-12-p18-method-source-persistence-design.md)。P16・P17 とまとめて 1.7.0 で出す（SPEC §2.4）。

## 前提

P17 緑（PR #29 マージ済み）。SPEC の P18 追記は実装より先。

## 範囲

**やる:** 版 4 のヘッダ（`sourcesBytes`）とソース節、ロードと保存の前検査（節の違反は `damaged image`、ヒープを載せる前に拒む）、ロードで戻したソースだけの項目、ロードのあとの形の変更・再 Accept・削除・2 回の往復、戻ったセットの File Out と Change Sorter のソース枠、CLI の `ao image save`（空の節）と `ao image load`（検査だけ）。

**やらない:** doIt のテキストの保存、ブロックとデバッグ情報（pc→ソース表、temp 名）の保存、Smalltalk のヒープへのソースの格納、Kernel の変更、版 3 の書き出し。
