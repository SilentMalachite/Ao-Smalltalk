## 前提

- ヒープは nursery（既定 1 MiB）と old（既定 4 MiB）に分かれる。`Heap::allocate` は nursery だけで、GC は生きている nursery オブジェクトを old へ昇格する。old には回収前のゴミと、immovable 用のフィラーが残る。だから old の memcpy はスナップショットにならない。
- 公開 OOP は `ao::Oop`。`raw_` は private。即値のビット列をファイルへ書くには `bits()` / `fromBits()` が要る。空の `Oop{}` は raw 0、`nil` は raw `0x4`、`false` は `0x0C`、`true` は `0x14`。この差を潰さない。
- `NativeMethod` は 6 スロット。関数ポインタはオブジェクトに無く、プロセス大域の `gNativeFns[index]` にある。名前は `kNativeSlotName` のバイトオブジェクト（クラスは `nil`）に `ao_Object_identityEquals` の形で既に入っている。レジストリは今、名前を覚えていない。
- `WellKnown` の固定スロットと `extra_` とシンボル intern 表は C++ 側のルートである。`Globals::install` の `smalltalk` はクラス `nil` の 57 スロット配列で、`kNames` に無い `Link` や `CmUser` は `atPut` されない。`named()` は `extra_` を見る。
- `ao::boot()` は `0` を返すだけでヒープを持たない。テストも CLI もスタック上の `Heap` を使う。インタプリタのオペランドスタックは C++ フレームにある。
- README の「P6 はまだ無い」は古い。この計画では README を直さない。
- グラフの AOIM コミュニティは PR 文書ノードだけである。実装時に `GRAPH_REPORT.md` を読み、`graphify query "AOIM NativeMethod WellKnown Heap"` で経路を取る。Serena の `activate_project` は grok の single_project では使えない。定義と参照は `find_symbol` / `find_referencing_symbols`、本体は `replace_symbol_body`。worktree は絶対パスで開く。

## 仕様

### ファイル配置（すべて little-endian）

ヘッダ 48 バイト。続くヒープ節、well-known 節、extra 節、globals 節。

| オフセット | 型 | 内容 |
|---|---|---|
| 0 | 4 bytes | `AOIM` |
| 4 | u16 | version = 1 |
| 6 | u16 | pointerBits = 64 |
| 8 | u16 | endian = 1（little） |
| 10 | u16 | headerBytes = 48 |
| 12 | u32 | heapBytes（16 以上、8 の倍数） |
| 16 | u32 | wellKnownCount |
| 20 | u32 | extraCount |
| 24 | u32 | globalCount（ブート後は 57。`smalltalk` が nil なら 0） |
| 28 | u16 | nextHash（0 は load 時に 1 として扱う） |
| 30 | u16 | 0 |
| 32 | u32 | 0 |
| 36 | u32 | 0 |
| 40 | u64 | 0 |

ヒープ節の先頭 16 バイトはフィラーである。オブジェクトは置かない。

```
klass = nil のビット 0x4
size  = 0
flags = kFlagBytes
hash  = 0
```

`objectBytes` は 16。GC が old を走査してもここでずれない。ファイルオフセット 0 は空 OOP のままなので、再配置で `oldStart_` を足さない。

それ以降は `ObjectHeader` と同じ 16 バイトヘッダとペイロード。バイトオブジェクトの端数は 0 埋めで 8 バイト境界まで。ポインタオブジェクトは `size * 8` で既に揃う。

ファイルに残してよい flags は `kFlagBytes` と `kFlagWeak` だけ。`kFlagOld` / `kFlagMarked` / `kFlagForwarded` / `kFlagImmovable` は落とす。load 後にアドレスで old と分かるので、ピンのアドレス保存はしない。`kFlagMarked` か `kFlagForwarded` が付いたオブジェクトを辿ったら save は失敗する。

### OOP エンコード

| 値 | ファイル上の u64 |
|---|---|
| 空 `Oop{}` | 0 |
| 即値（SMI / Character / nil / true / false） | `Oop::bits()` そのまま |
| ヒープ | ヒープ節先頭からのオフセット。16 以上、8 の倍数、オブジェクト先頭だけ |

下位 3 ビットが 0 かつ非 0 の値だけをヒープオフセットとして読む。load はそのオフセットがオブジェクト先頭表に無いとき失敗する。ホストポインタは書かない。

### well-known 節

レコードは `u32 nameLen`、`nameLen` バイトの名前、4 バイト境界までの 0 パッド、`u64` OOP。`nameLen` は 1 以上 256 以下。

`WellKnown::eachImageSlot` が保存順の唯一の一覧である。`kNamedClasses` の順に `"Object"`、`"Object class"`、…、`"Time"`、`"Time class"`（56 クラス × 2）。続けて `"Smalltalk"`、`"Processor"`、`"transcript"`（インスタンス。クラス `Transcript` とぶつからないように小文字）、続けてセレクタ `"value"` `"value:"` `"new"` `"basicNew"` `"basicNew:"` `"size"` `"at:"` `"at:put:"` `"do:"` `"error:"` `"class"` `"=="`。合計 127。

load は名前でスロットへ束縛する。未知の名前、127 件の欠落、カタログ名の重複は失敗。

### extra 節

`extra_` の挿入順。レコード形式は well-known と同じ。値はクラス OOP。カタログ名（`isCatalogName`）が混ざっていたら save も load も失敗する。load は `define()` する。`define()` は `kNames` に無い名前を `smalltalk` 配列へは書かない。これは今の file-in と同じである。

### globals 節

`kNames` の 57 名前と、`smalltalk` 配列の対応スロット。新しい辞書は作らない。load は束縛後の配列スロットとレコードが一致することを確かめる。`Processor` レコードは `wk.processor`（インスタンス）と一致する。`Transcript` レコードはクラスの方である。

### save

1. ルート（`Roots::visitAll`）から強参照だけを辿る。弱スロットは辿らない。クラススロットは弱オブジェクトでも辿る。
2. 先頭出現順でオフセットを振る。先頭は 16。
3. 弱スロットの参照先が保存集合に無ければ、ファイル上のそのスロットは `nil`（`0x4`）。元ヒープは変えない。
4. バイト列は `size` バイトだけコピーし、パッドは 0。
5. `nextHash` は `Heap::hashCursor()`。

### load

destination は old が空の `Heap`。失敗のとき `adopt` より前に返り、ヒープは空のままである。

1. ヘッダと三つの節を検証する。
2. `kernel::ensureNativeNames()`。`ao_Object_identityEquals` がレジストリに無ければ、捨てる専用の `Heap` で `Bootstrap::run` し、`putNative` に名前を登録させる。destination は触らない。
3. ファイル上で `NativeMethod` の名前がすべて `findName` でき、シンボルのバイト列が重複していないことを確かめる。
4. `heapBytes` が old 容量以下なら `adoptOldBytes` でヒープ節を old の先頭へコピーし、`nextHash` をセットする。
5. 非 0 のヒープオフセットに `oldStart_` を足す。0 と即値はそのまま。flags に `kFlagOld` を足す。
6. well-known を束縛し、extra を `define` し、シンボルを `rememberSymbol` し、NativeMethod の `kNativeSlotRegistryIndex` を名前から書き直す。
7. globals 節と `smalltalk` 配列を照合する。

### CLI

```
ao image save <path>
ao image save --load-order <LOAD_ORDER> <path>
ao image load <path>
```

`save` は今の `filein` と同じブートをする。`--load-order` のときだけ `fileInLoadOrder` してから保存する。`load` はブートせずに読み、`1 + 2` が SmallInteger の 3、`nil isNil` が true なら exit 0。使い方の誤りは exit 2、失敗は exit 1。`--help` にこの 3 行を足す。

- [ ] **Step 1: 失敗するテストを書く**

同じ `image_save_load_test.cpp` に次を足す。

1. `ImageSaveLoad.OnePlusTwoMatches` — save して `Loaded` へ load。`1 + 2` が 3。`nil isNil` が true。`Object new class == Object`。`Metaclass class class == Metaclass`。
2. `ImageSaveLoad.UserMethodSurvives` — `CmUser>>ok`（`^1 + 2`）と `CmUser>>tag`（`^'ao'`）を file-in して save/load。`named("CmUser")` の identity hash が保存前と一致。`lookup(..., intern("ok"))` のクラスが `compiledMethodClass`。インスタンスへ `ok` を送ると 3、`tag` を送ると UTF-8 の `ao`。`nativeCode` スロットは nil。
3. `ImageSaveLoad.KernelMethodsStayNative` — load 後、`eachNativeRequiredClass` のメソッド辞書の値（と、そのクラスの metaclass 側）がすべて `nativeMethodClass`。辞書の歩き方は `kernel_scan_test.cpp` の `kDictSlotArray` と同じ。
4. `ImageSaveLoad.SymbolIdentity` — load 後 `intern("ok") == intern("ok")`。`lookup` のキーと `intern("ok")` が `==`。
5. `ImageSaveLoad.WeakSlotNilsUnreachable` — 弱配列だけをルートした save を load し、そのスロットが nil。元ヒープのスロットは nil になっていない。参照先も別にルートしたときは load 後も同じ中身へ届く（文字列バイトで比較する。ポインタ値は一致しない）。
6. `ImageSaveLoad.RejectsBadMagicAndSecondLoad` — マジックを壊したファイルは false で、destination の `oldUsed()` は 0。成功した load のあと同じヒープへもう一度 load すると false。
7. `ImageSaveLoad.NurseryGcAfterLoad` — load 後に nursery を埋めて `Gc::collectNursery()` し、もう一度 `1 + 2` が 3。
8. `ImageSaveLoad.VendorLinkSurvives` — `fileInLoadOrder(AO_SOURCE_DIR "/image/vendor/LOAD_ORDER")` のあと save/load。`named("Link")` がヒープで、`lookup` した `nextLink` のクラスが `compiledMethodClass`。`Link new nextLink` は nil（空リンク）。このテストの destination が容量不足で false になったら、既定の `Heap` コンストラクタは変えず、ファイルの `heapBytes` 以上の old を持つ `Loaded` 用ヒープだけを使う。CLI の既定 4 MiB に入るかは Task 5 で測る。

`tag` の methodsFor は `ok` とは別チャンクにする。

  ^'ao'!

## リスク

- vendor イメージが old の 4 MiB を超えると CLI load が失敗する。そのときはバイト数を報告し、既定容量は変えない。
- `ensureNativeNames` はプロセス内で一度だけフルブートする。登録順は `putNative` のままなので、既存テストのレジストリインデックスは変わらない。
- save はインタプリタフレームを残さない。file-in と send が返ったあとだけ呼ぶ。
- クラス名と NativeMethod 名はクラス `nil` のバイト列である。Symbol ではない。再結合は Symbol intern と混ぜない。
