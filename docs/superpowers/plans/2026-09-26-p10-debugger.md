# P10 事後デバッガ Implementation Plan（P11 ライブデバッガの設計を含む）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Workspace の評価が失敗したとき（`nil foo`、`self error:`、`self halt`、ネイティブの失敗）、巻き戻す前のスタックを捕らえ、Ao.app の Debugger 窓で「フレーム一覧 / 失敗した送信を選択したソース / receiver と temps の値」を見られるようにする。Proceed / Step は P11。

**Architecture:** 解釈フレームの C++ 側の状態（`Temps` / `OperandStack`）を `CallContext::topFrame` の連鎖でたどれるようにし、`abortEvaluation` が最初の理由を固定した瞬間に、セッション所有のルート付きスナップショットへ写す。ネイティブは連結しない（失敗したネイティブのフレームは最内の解釈フレームの進行中の送信から合成する）。pc→ソース表と temp 名はコンパイラの `MethodImage` に出し、セッションのソース表に置く。イメージには何も足さない（CompiledMethod は 6 スロットのまま、版 3 のまま）。ホストは `ao_debug_*` の C ABI で読む。

**Tech Stack:** C++20、GoogleTest、Swift 6 + AppKit、XCTest。既存の `Interpreter` / `Send` / `Session` / `Roots` / `MethodImage` / `Emitter` / `WorkspaceWindow` / `InspectorWindow`。新規ライブラリは足さない。

**Spec:** P10-01 で `SPEC.md` を先に直す（下の「SPEC を先に直す」）。フェーズ正本は `docs/phases/P10.md`、PR 骨格は `docs/prs/P10-01.md` … `P10-07.md`。P11 の正本は `docs/phases/P11.md`（PR 指示書は P10 完了後）。

## 結論

v1（P9）は 1.0.0 としてリリース済みで、`PHASE` は `P9`、`main` は `7262952`。SPEC §1.4 / §5.4 / §3.9、CLAUDE.md の禁止リスト、CHANGELOG の Known limitations はどれもデバッガを範囲外としている。だから最初の PR は SPEC と CLAUDE.md の改訂であり、コードはそのあとである。

P10 は **事後（post-mortem）** デバッガである。失敗は今までどおり abort して最外まで巻き戻る。変わるのは、巻き戻す前にスタックを写して残すことと、それを見る窓が増えることだけである。評価の意味論、`ao_eval` の返り値、`ao --test`、CLI、イメージ形式は変えない。

P11 は **ライブ** デバッガ（`halt` で止めて Proceed / Abort / Step）である。P10 の連鎖と ABI をそのまま使えるように、P10 の時点で「フレームの供給元」を抽象にしておく。P11 の設計判断は本計画の末尾と `docs/phases/P11.md` に固定する。

## 前提

### ランタイム（設計検証で確認した事実。行番号は `main` 7262952）

- 解釈実行の 1 活性化ごとにヒープのコンテキストを先に作る（`Interpreter::run`、`runtime/src/Interpreter.cpp` 470–871 行）。スロットは `kCtxSender / kCtxPc / kCtxStackp / kCtxMethod / kCtxReceiver / kCtxArgc`、ブロックは `kBlockHome / kBlockCopied`（`runtime/include/ao/Context.hpp`）。
- `mirror()` が各バイトコードの先頭で pc をコンテキストに書く。呼び出し元のコンテキストの pc は、実行中の Send 命令の先頭を正確に指す。
- **temp とオペランドスタックはヒープに無い。** `Frame{method, receiver, context, pc, isBlock}` / `Temps` / `OperandStack` は `Interpreter::run` の C++ スタック上にある匿名名前空間の型である。ガードの宣言順は frame → `FieldRoots` → `DepthGuard` → `NonlocalGuard` → コンテキスト生成 → `ContextExitGuard`（退出時に pc と sender を nil）→ `ActiveGuard` → `Temps` → `OperandStack`（551 行）。
- `performSend`（404–438 行）は receiver と args をルート済みの `rcvr.slot` / `argv` に降ろしてから `send` / `sendSuper` を呼ぶ。結果が空 OOP で巻き戻し中でなければ `abortFailedSend`。
- ネイティブはコンテキストを積まない。`NativeMethod::invoke`（`runtime/src/NativeMethod.cpp` 120–152 行）は `NativeFrame`（ルートのスロットのみ）を積む。`applyMethod`（873–898 行）が全送信の唯一の入口で、フレームを作る前にスタックガードで abort する。
- abort は `abortEvaluation(ctx, const char*)`（`runtime/src/Send.cpp` 233–241 行）だけが始める。`if (!ctx.aborting)` の中で最初の理由を固定する。string_view 版（243–255 行）は String を割り当ててハンドルに積んでから委譲する。その瞬間 `ctx.activeContext` は最内の生きたコンテキストで、sender 連鎖は最外まで無傷である。**巻き戻しが終わると連鎖は死に、`sessionEval` が理由を読む時点では何も残っていない。**
- `ensure:` の後始末は `runAside`（`runtime/src/kernel/BlockContext.cpp` 57–90 行）が abort 状態を退避して `clearUnwinding` してから走る。後始末の abort は `aborting == false` で `abortEvaluation` に再入する。
- Scheduler も `abortEvaluation` を使う。失敗でない巻き戻しは、呼ぶ前に印を立てる。自プロセスの `terminate` は `me.terminated = true`（`runtime/src/Scheduler.cpp` 509–512 行。同じ行がベースへの `terminate` にも使われ、そちらは失敗）、他プロセスからの `terminate` は 857–858 行、abandon は `ctx.abandoning = true`（848 行）→ 852 行。deadlock（832、863 行）、`too many processes`（349、361 行）、`process cannot run`（490 行）は §3.3 の失敗である。

### フレーム連鎖（P10-03）

- `Frame` / `Temps` / `OperandStack` を非公開ヘッダ `runtime/src/InterpFrame.hpp` に移す（`Session.hpp` / `Fiber.hpp` と同じ「公開しないヘッダ」の慣習）。
- `Frame` に足す: `Frame* prev`、`const Temps* temps`、`const OperandStack* stack`、進行中の送信 `Oop sendSelector`、`const Oop* sendReceiver`、`const Oop* sendArgs`、`std::uint32_t sendArgc`。`performSend` が `send` / `sendSuper` を呼ぶ前にルート済みの `rcvr.slot` / `argv` を指して設定し、戻ったら消す。
- `CallContext` に `Frame* topFrame = nullptr` を足す。連結ガード（RAII）は **`OperandStack stack(ctx.roots);`（551 行）の直後** に宣言する。退出で最初に外れるので、`topFrame` が消えた `Temps` を指すことはない。`ContextExitGuard` より前に外れる。
- `CallContext` はプロセスごとなので、`switchTo` は `topFrame` を保存 / 復元しない。`switchTo` はフックと同じ場所（887–891 行）で `debug`（下）を写す。
- **ネイティブは連結しない。** `NativeMethod::invoke`、`NativeFrame`、`answerWithoutSend`、SmallInteger の高速路は変えない（SPEC §1.3）。失敗したネイティブのフレームは、捕捉時に最内の解釈フレームの進行中の送信から合成する（receiver / args / selector と、割り当てなしの `lookup` で引いた NativeMethod）。
- `applyMethod` のスタックガードはフレームを作る前に abort するので、最内は再帰している呼び出し元で、進行中の送信が立っている。捕捉は反復で行い（再帰しない）、予約分の中で終わるように小さく保つ。
- 性能: 解釈送信 1 回につき `performSend` に 4 ストアと 1 クリア、活性化 1 回につき連結 / 解除 1 回。`KernelBench.*` と `docs/bench.md` の比で確認する。

### pc→ソース表と temp 名（P10-02）

- `MethodImage` に `std::vector<PcSpan> pcMap`（`{pc, start, end}`）と `std::vector<TempName> temps` を足す。`Literal` は `MethodImage` を深くコピーするので、それ以外は変えない。`disassemble` は変えない。
- `Emitter::mark(SourceSpan)` は `{bytes.size(), span}` を `pcMap` に足す。呼ぶ場所: `compileSend`（`send.span`）、`compileCascade` の各パート、`compileReturn`（`n.span`）、`compileInlined` の `JumpTrue` / `JumpFalse`（**レシーバの span**。`NonBoolean receiver` が条件式を指すように）、`compileToDo` の `SendSpecial`（`send.span`）、`compileStmt` の各文の先頭。Send / SendSuper / SendSpecial / Jump* / Return* / ReturnBlock の **直前** に呼ぶ。pc について単調なので整列済みである。引くときは「pc 以下で最大のもの」（Send は一致する）。
- ブロックは `compileBlock` が作る自分の `MethodImage` に自分の表を持つ。座標は外側メソッドのソースと同じ（ブロックのフレームは同じテキストの中を強調する）。入れ子も同じ。
- temp 名: `compileMethod` / `compileBlockMethod` で `real_->vars`（`VarKind::Hidden` を除く）から `{name, kind, slot}` または `{name, kind, vectorTemp, vecIndex}` を出す。捕捉した外側変数は `real_->copied` から、`Capture{var}` → `{name, copiedIndex}`、`Capture{vector, owner}` → そのベクタに置いた各変数について `{name, copiedIndex, vecIndex}`。展開したブロックの temp は宣言した実スコープに入っているので、これで含まれる。
- doIt: `evalBody` は `"doIt\n"` を前置するので、表の座標は `kDoItPrefix`（5）を引いて外に出す（記録時に引くか、`sourceOffset` を持って読み出し時に引く）。

### ソース表の拡張（P10-04）

- `MethodSource` に足す: ブロック CompiledMethod のルート付きスロット（アドレスが安定な置き方。リテラル添字で本体と対応付け、入れ子は前順）、`std::shared_ptr<const DebugInfo>`（本体と各ブロックの `pcMap` と `temps`）、`sourceOffset`。
- `rememberMethodSource(kept, text, replaced, &cr.image)`。`acceptMethodSource` の 1396–1409 行で `cr.image` と `kept.slot` が揃っているので、そこから渡す。
- `moveMethodSource(from, to)` は、形の変更で新しく箱詰めされたブロックを `to` のリテラルを同じ前順で歩いて付け直す。`DebugInfo` はそのまま。
- `Session::doItDebug` は直前の `ao_eval` の doIt の 1 件だけ（method、ブロック、text、DebugInfo）を持つ。`sessionEval` の入口で消し、`evalBody` が箱詰めのあとに入れる。
- `methodSourceRootSlots` はブロックのスロットとスナップショット（下）のスロットも返す。`HideMethodSources`（イメージ保存）と `liveClasses`（形の変更の生存判定）はそのまま `methodSourceRootSlots` を使うので、両方が隠す。
- `Session::debug`（スナップショット）は `roots` より **あと** に宣言し、先に壊れるようにする。

### 捕捉（P10-03、配線は P10-04）

- `CallContext` に `DebugSink* debug = nullptr` と `std::uint32_t abortSetAside = 0` を足す。`DebugSink` は `runtime/include/ao/DebugSnapshot.hpp` の純粋仮想（`void onAbort(CallContext&) noexcept`）。Send.cpp は Session を知らない。`Boot` 層のテストは自前の sink を差す。
- `abortEvaluation(ctx, const char*)` の `if (!ctx.aborting)` の中で、理由を固定し `dropNonlocal` したあとに `if (ctx.debug && !ctx.abandoning && ctx.abortSetAside == 0) ctx.debug->onAbort(ctx);`。string_view 版はハンドルを積んでから委譲するので `abortReasonText` が使える。
- `abortEvaluationQuiet(ctx, reason)`: 同じ意味で、捕捉だけしない。Scheduler.cpp 858 行（他プロセスからの `terminate`）と 852 行（abandon）に使う。512 行は `r == &me && !me.isBase()` のとき quiet、ベースなら普通の abort に分ける。deadlock、`too many processes`、`process cannot run` は普通の abort のまま（§3.3 の失敗）。
- `runAside`: 退避した `aborting` が true のときだけ `++ctx.abortSetAside`（71 行）/ `--`（73 行）。後始末の中の abort は最初の理由を保つので捕捉しない。正常終了のあとの後始末の失敗は捕捉する（そのときは 0 のまま）。
- `DebugSnapshot::capture(CallContext&) noexcept`: `ctx.topFrame` を反復で歩き、フレームごとに種類（0 method / 1 block / 2 native 合成）、method、receiver、context、pc（コンテキストの `kCtxPc`）、selector（進行中の送信）、temps（`Temps` の写し）、進行中の送信の args を、**Smalltalk ヒープを割り当てずに** `std::unique_ptr<Oop[]>` へ写す。写し終えてから各スロットを `roots.add` する（読みと登録の間に GC は入らない）。消すときは **逆順** に `roots.remove` する（`Roots::remove` は末尾から探す）。理由は `abortReasonText` の写し（C++ 文字列）。`activeProcess`（ルート）と、ベースからかどうかも記録する。上限は最内 256 フレーム + 総数。`std::bad_alloc` は捕捉を捨てる。
- 最内の解釈フレームに進行中の送信があり、その送信がネイティブに当たった（`lookup` の答えが NativeMethod）なら、そのネイティブを kind 2 のフレームとして最内に合成する。DNU なら、セレクタだけの kind 2 フレーム（method 無し）を合成する。
- 1 セッション 1 枠。ベースの捕捉は常に置き換える。ファイバの捕捉（`runFiber` の abort）は空のときだけ埋める。`sessionEval` の入口、`ao_debug_clear`、ロード、shutdown で消す。捕捉と消去のたびに `generation` を増やす。
- `ao_debug_*` の printString / inspect の間は `ctx.debug = nullptr`（それ自身の abort で置き換えない）。

### P11 ライブデバッガの設計判断（P10-01 で SPEC §3.13 に書く）

- **評価プロセス**: ホストが `ao_set_debug_mode(AO_DEBUG_LIVE)` を有効にしたとき、`ao_eval` の doIt をベースでなく fork したプロセスで走らせる。ベースは `terminate` の「相手の終わりを待つ」機構（`resumeTo`）と同じ形で待ち、評価プロセスが切り替えたら drain と同じ規則で回し、終わるか止まるかで `ao_eval` から戻る。ライブモードでない評価（CLI、`ao --test`、既定）は変えない。
- **止める**: 評価プロセスでは `halt` / `error:` / DNU / `failed: #sel` / `NonBoolean receiver` / `cannot return` は、巻き戻す前にそのプロセスを止める（`suspend` と同じ状態 + 理由）。`ao_eval` は `AO_ERR_HALT`（6）と理由を返す。stack overflow、out of memory、deadlock、プロセス操作の失敗は止めず、今までどおり abort（P10 の捕捉が残る）。
- **フレームの供給元**: 止まったプロセスのフレームは、スナップショットでなく `ctx.topFrame` の生きた連鎖から読む。P10 の `ao_debug_frame_*` は「スナップショット」と「止まったプロセス」を同じ形で読めるように、P10 の時点で供給元を C++ の抽象（`DebugFrames` インタフェース: `count`、`kind`、`method`、`receiver`、`pc`、`selector`、`tempCount`、`temp`）にしておく。
- **操作**: `ao_debug_proceed(pid)` = resume して、止めた送信の値として nil を返す（Blue Book）。`ao_debug_abort(pid)` = terminate（後始末を走らせる）。`ao_debug_step_into / over / out(pid)` = プロセスごとの `stepMode` を立てて resume。インタプリタループの先頭で 1 分岐。step into はネイティブに入らない（次の解釈フレームの先頭で止まる）。どれも `ao_eval` の末尾と同じく、終わるか止まるまで回して結果（`out` / `AO_ERR_HALT` / `AO_ERR_EVAL`）を返す。
- **Debug it**: Smalltalk メニューに `Debug it`（⌘⇧D）。最初のバイトコードで止める。
- **busy とイメージ**: 止まったプロセスは走っていないので busy でない。デバッガを開いたまま別の Do it ができる。同時に止まれる評価プロセスは 8 まで。止まったプロセスはファイバの C++ スタックを持つのでイメージに書けない。`ao_image_save` は止まったプロセスがあれば `AO_ERR`（理由 `halted processes`）で拒む。
- **やらない**: Restart（フレームの再実行）、デバッガ内での編集 + Accept、temp の書き換え、ネイティブへの step into、ベースの停止。

## リスク

- **メモリ**: スナップショットが receiver と temps を次の評価まで生かす。上限（256 フレーム）で抑え、SPEC に書く。
- **古いデバッグ情報**: 再 Accept したメソッドのフレームは `replaced` で旧項目が消えるのでプレースホルダに落ちる。許容し、SPEC に書く。
- **`Roots::remove` の計算量**: 逆順に消さないと O(n²)。`clear()` で守る。
- **隠し忘れ**: `liveClasses` とイメージ保存がスナップショットとブロックのルートを見ないよう、`methodSourceRootSlots` 経由で隠す。`SessionAbi.ImageSaveDoesNotTraceSnapshotOrBlockSlots` で守る。
- **ベース優先**: ファイバの捕捉が drain 中にベースの失敗を隠さない。`DebugAbi.ProcessFailureIsReadableAfterEval` と `DebugSnapshot.FiberFailureCapturesOnItsOwnChain` で守る。
- **性能**: `performSend` の 4 ストア + `run` の連結 1 回。`docs/bench.md` の比が悪化したら、進行中の送信の記録を `ctx.debug != nullptr` のときだけにする（分岐 1 つ）。
- **ファイバと ASan**: 捕捉は普通の C++ なので追加の印は要らない。`finishFiber` の中では何もルートしない（Scheduler.cpp 711–713 行）。
